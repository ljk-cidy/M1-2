## 데이터 성격

추가 데이터의 출처는 이 저장소의 seed_data.json입니다. **실제 관측에서 수집한 데이터가 아닌 학습용 예시**이며, 10가지 값과 메모가 10일마다 반복됩니다. 서로 다른 날짜의 데이터 포인트 100개로 구성되어 있습니다. 기존 기록 1개와 함께 서비스에 저장했습니다.

개수와 형식 검증을 통과했지만, 실제 학습 습관에 관한 결론이나 예측의 근거로 사용하지 않습니다. 실제 수집 데이터가 필요한 평가 기준이 추가로 있다면 해당 출처의 데이터로 교체해야 합니다.

## 검증 절차

1. Pydantic 모델로 샘플 100개를 검증하고 날짜 중복·연속성·시간 범위를 확인했습니다.
2. 기존 DB 전체를 로컬에 백업하고, 적재할 sample-* ID에 다른 데이터가 없는지 확인했습니다.
3. python -m scripts.seed로 적재한 뒤 실제 DB 문서를 원본과 대조했습니다.
4. 기존 기록 불변, 샘플 100개 일치, 전체 101개 모델 검증 통과를 확인했습니다.
5. 실제 /api/data 및 /api/data/summary를 재조회하여 개수가 일치하는지 확인했습니다.

# 최초 점검: 적재 전 1개 상태

점검일: 2026-10-18 · 대상: 로컬 API가 연결한 실제 Firestore

**현재 최소 100개 기준 미충족: 저장된 데이터 1개, 부족분 99개.**

| 확인 대상 | 결과 | 판정 |
| --- | --- | --- |
| GET /api/data | 1개, 모델 검증 통과 1개 | 최소 개수 미달 |
| GET /api/data/summary | count=1, 기간 2026-10-18 하루 | 목록 개수와 일치 |
| seed_data.json | 100개, 서로 다른 날짜 100개 | 파일 준비 완료 |
| 샘플 기간 | 2026-06-01 ~ 2026-09-08 | 100일 |
| 샘플 적재 ID | 실제 DB의 sample-* 문서 0개 | 현재 DB에 샘플 미적재 |
| 샘플 패턴 | 값 10종·메모 10종이 10일마다 반복 | 반복 예시 데이터 |

## 문제와 원인

1. **파일과 서비스 데이터가 다릅니다.** 샘플 파일이 저장소에 있어도 API는 Firestore만 조회합니다. 서버 시작이나 GitHub 푸시로 샘플이 자동 적재되지는 않습니다.
2. **현재 DB에 가져오기가 반영되지 않았습니다.** scripts/seed.py는 별도 실행해야 합니다. 이전 실행 여부나 다른 Firebase 프로젝트에 적재했는지는 이번 점검만으로 확정할 수 없습니다.
3. **데이터의 성격을 구분해야 합니다.** 현재 샘플은 값과 메모가 반복되는 예시 데이터이며 실제 관측 기록이라는 근거가 없습니다. 미션 문구의 개수 조건과 별개로, 출처·수집 방법·단위를 설명하고 예시 데이터임을 밝혀야 합니다.
4. **이전 미리보기의 101개는 실제 DB 증빙이 아닙니다.** README 미리보기는 메모리 DB와 모의 GPT 응답을 사용한 UI 테스트 화면입니다. 현재 실제 Firestore 개수와 구분해야 합니다.
5. **1개로는 추세를 판단하기 어렵습니다.** 현재 API의 ‘유지 추세’는 단일 값에 대한 기본 표시입니다. 실제로 학습량이 유지된다는 분석 근거로 사용하기 어렵습니다.

## 조치 순서

- 데이터 선택: 실제 학습 기록 또는 출처를 밝힌 시계열 데이터 100개 이상을 준비합니다. 현재 예시 데이터를 사용할 경우 그 성격을 README에 명시합니다.
- 적재: 기존 데이터는 보존하고, 확정한 데이터를 Firestore에 가져옵니다. 현재 샘플 적재 명령은 저장소 루트에서 python -m scripts.seed입니다. sample-000 등의 문서는 재실행 시 덮어씁니다.
- 검증: 실제 API 목록과 summary.count가 모두 100 이상인지 확인하고, 날짜·수치·누락·중복·단위를 점검합니다.
- 제출: 실제 데이터가 표시되는 화면으로 캡처하고, 준비 데이터 개수·기간·출처를 문서에 남깁니다.

이번 작업은 조회와 문제 정리만 수행했으며, 실제 DB 데이터는 추가·수정·삭제하지 않았습니다.
